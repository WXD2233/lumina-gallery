# 拾光 · Lumina

本地图片集管理软件，通过浏览器使用。图片保存在自己的电脑上，可为每组图片添加网盘链接，并在标题下显示更新时间。

## Linux VPS 一键部署

公开仓库：[WXD2233/lumina-gallery](https://github.com/WXD2233/lumina-gallery)。在准备好域名并开放 80/443 的 VPS 上执行：

```sh
curl -fsSL --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/WXD2233/lumina-gallery/main/scripts/lumina.sh -o lumina.sh && sudo bash lumina.sh install
```

安装后用 `sudo lumina setup-admin` 创建管理员；`sudo lumina upgrade` 升级，`sudo lumina uninstall` 卸载，`sudo lumina` 打开管理菜单。卸载默认保留图库和配置；升级先保留一致的数据库快照，启动失败会恢复上一版。发布包提供 Linux x64 / ARM64 镜像，并通过 SHA-256 校验。详细要求、迁移和排错见 [INSTALL.md](INSTALL.md)。

## Windows 启动

双击 **`start.cmd`**，等待浏览器打开 `http://127.0.0.1:3210`。首次启动会安装依赖并构建页面，需要网络连接。

需要 **Node.js 22.13 或更高版本**，推荐安装 [Node.js LTS](https://nodejs.org/)。启动器会优先寻找已安装的 Node.js，也支持当前用户目录内的 Codex 捆绑运行时。运行期间保留终端窗口，按 `Ctrl+C` 停止服务。也可执行 `start.cmd -NoBrowser`，只启动服务。

软件已经运行时，再次双击启动器会直接打开现有页面，不会再启动一个服务。

### 首次设置与登录

首次打开时显示“设置图库登录”窗口，请在运行服务的电脑上通过 `http://127.0.0.1:3210` 设置自己的用户名和密码。用户名为 2–40 个字符，新密码为 15–128 个字符，并拒绝常见弱口令、简单重复及连续序列；推荐使用不与其他网站共用的长密码或短语。软件没有默认账号或默认密码。已设置的旧密码仍可登录，下次修改密码时使用新要求；尚未设置账号的已有图库升级后先创建账号，原有图集、分类和图片保留。

之后访问图库需要先登录。登录状态最长保留 8 小时，到期后重新登录；可在“图库设置”底部点击“退出登录”结束会话，也可在“图库设置 → 账户与头像”中展开“修改登录密码”。点击右上角头像同样可进入账户与头像设置。修改密码需要当前密码，完成后其他登录会话失效。图片原图、缩略图、图库接口和备份下载同样要求登录，不能通过直接访问地址绕过登录窗口。

图库支持管理员和普通只读账户，不提供公开注册，账户由管理员在设置中创建。多个账户共同访问同一份图库。退出登录只结束浏览器的访问会话；只要软件服务仍在运行，原有每日网盘检测与时间同步会继续执行。

### 密码与传输保护

没有默认密码，也不会将已保存的登录、SMTP 或 WebDAV 密码写入前端构建文件、浏览器存储、日志或图库备份。登录密码在服务器保存为带随机盐的 scrypt 哈希；SMTP/WebDAV 密码在服务器加密保存，设置接口只返回是否已配置，不回显原值。切换设置页、收起改密表单或提交完成后，会清除相关输入。

启动服务默认拒绝公网 HTTP 请求，HTTPS 响应包含 HSTS；只有真正直接连接本机的 `localhost`、`127.0.0.1`、`[::1]` 请求可使用 HTTP。页面在其他 HTTP 地址下不会显示登录输入或发出图库 API 请求。Docker 宿主机端口转发不属于容器内的直接回环连接，应通过 HTTPS 反向代理访问。

用户刚输入的密码仍会短暂存在于自己的浏览器中，并通过 HTTPS 请求交给服务器验证；浏览器开发者工具可以看到本人提交的内容。HTTPS 防止网络途中的被动截获，不能保护已被恶意扩展或恶意软件控制的浏览器。前端固定密钥或简单哈希不能替代 HTTPS。下载资源的提取码、解压码属于图库资料，仍按账户权限显示和导出。

### 管理员与普通账户

已有版本升级后，原账户自动成为管理员，原有密码、登录会话和头像会保留。进入“图库设置 → 账户管理”，管理员可新增账户、修改其他账户的用户名和角色、重置密码、启用/禁用或删除其他账户。

- **管理员**：可管理图集、分类、网盘同步、导入备份、账户和邮件提醒。
- **普通只读账户**：可浏览、搜索、查看网盘资源、下载原图及导出图库备份；可修改自己的头像和密码。不能上传、编辑、删除图集，也不能改变共享收藏、分类、同步设置或导入备份。
- 禁用、删除、重置密码或调整权限后，目标账户原有会话会立即失效。删除账户不会删除共享图库。
- 当前账户不能在账户管理中编辑或删除自己；自己的密码通过“账户与头像”修改。系统保护最后一个可用管理员。
- 每个账户的头像和登录会话独立。图库 Excel / ZIP 备份不包含账户、头像、SMTP 凭据、安全记录或登录会话；导入图库备份不会覆盖这些配置。

### 邮件安全提醒

进入“图库设置 → 安全提醒”，填写 SMTP 服务器、加密方式、端口、发信账号、授权码/密码、发件地址和收件邮箱（最多 10 个）。先保存，再点击测试邮件；确认收到后开启邮件提醒并保存。测试邮件每分钟最多发送一次，也可以在自动提醒关闭时测试。SMTP 凭据需要使用邮箱服务商提供的配置，页面不会回显已保存密码；密码栏留空保留原值，勾选清除才会删除。未配置邮箱时不会发送邮件。

可分别开启“新来源登录”和“疑似暴力破解”提醒。新来源指该账户的已知来源记录中尚未出现的网络来源；同一来源再次登录不会反复提醒。每个账户最多记住最近使用的 256 个来源，超过 180 天未使用的来源会清除，之后再次登录会按新来源处理。IPv4 映射地址统一识别，IPv6 按 /64 网络合并。来源取自实际网络连接，不信任客户端提交的转发头；反向代理部署时可能统一显示代理地址，因此不能当作设备识别。

同一来源触发暴力破解限制时，15 分钟内合并为一条记录；不同来源的攻击邮件每分钟最多一封，所有自动提醒合计每 15 分钟最多 20 封。临时网络故障最多重试一次；邮箱认证等永久错误不自动重试。页面显示最近 100 条安全记录，已处理记录最多保留 90 天、最多 1000 条，待发送记录单独保留。可查看事件时间、来源及邮件发送结果；发送失败不会阻止正常登录。

邮件传输强制使用 465 端口的 SSL/TLS，或 587 端口的 STARTTLS，并验证服务器证书。提醒包含必要的账户名、来源、客户端信息、事件和时间，不含登录密码、会话 Cookie 或图库内容。SMTP 授权码使用 AES-256-GCM 加密存入数据库，解密密钥保存在数据目录的 `security-mail.key` 中；应随完整数据目录一起保管，密钥丢失后需要重新填写授权码。服务关闭时无法发送；服务运行且邮箱配置有效时才会处理提醒。

### 防撞库与暴力破解

服务端对登录、首次设置和修改密码分别限制尝试次数，浏览器也会显示剩余等待时间：

- 登录与首次设置分别计数：同一真实连接来源在 10 分钟窗口内最多尝试 10 次，全站同一操作最多尝试 60 次；成功验证不会清除这个尝试次数窗口。
- 修改自己的密码按已登录账户独立计数：同一账户、同一来源在 10 分钟内最多尝试 10 次，该账户跨来源合计最多尝试 60 次。一个账户的错误尝试不会消耗其他账户修改密码的额度，也不与公开登录共用额度。
- 在上述各自的计数范围内，同一来源失败达到 5 次，或跨来源累计失败达到 10 次，开始等待 30 秒；冷却后继续失败会逐次延长，最长等待 15 分钟。等待期间继续请求不会延长冷却。24 小时没有新失败后重置失败进度；冷却结束后的成功验证会清除对应来源及跨来源的失败进度。
- 限制状态保存在数据库中，重启服务不会解除限制。更换用户名或伪造 `X-Forwarded-For` 等请求头不能换一个来源重新尝试。经反向代理访问时，当前按代理的实际连接地址合并计算来源限制。
- 公开登录和首次设置最多同时执行 3 次密码计算，另为已登录的修改密码保留计算容量。公开登录进入冷却不会注销已有会话，也不会占用修改密码的次数窗口；已登录后仍可浏览图库、修改密码和退出登录。

登录凭据错误时统一提示用户名或密码不正确，不透露账号是否存在。密码使用加盐 scrypt 哈希保存；新密码的弱口令检查在本机完成，不上传密码。软件导出的 Excel 和 ZIP 不包含账号密码、会话或限流状态。以上措施减少自动猜测的机会，仍需使用独立密码；向公网开放服务时应通过 HTTPS 访问。

命令行启动：

```powershell
npm install
npm run build
npm start
```

开发模式执行 `npm run dev`；默认地址同为 `http://127.0.0.1:3210`。测试执行 `npm test`。

## 使用方式

侧栏“图库设置”统一管理账户与头像、网盘同步、备份与恢复、账户管理、安全提醒和使用说明，窗口底部可退出登录。普通账户仅显示其有权使用的项目。

在“账户与头像”中上传或更换头像，也可恢复默认的账号首字头像。支持 JPG、PNG、WebP、GIF、AVIF，单张最大 5 MB；图片自动居中裁成正方形，动图使用首帧。头像保存在运行服务的设备上，刷新或重启后仍然保留，只有登录后才能访问。头像属于账户资料，不包含在图库 Excel / ZIP 备份中，导入图库备份也不会修改当前头像。

- 新建图片集，输入标题、分类、标签和说明，导入多张图片。
- “导入图片”或“编辑图集”窗口支持切换“本地图片 / 网络图片”。网络图片可粘贴 `[img]https://example.com/photo.jpg[/img]`，也支持每行一个普通 HTTP / HTTPS 图片网址、多个 BBCode 图片标签以及论坛常见的 `[url=…][img]…[/img][/url]` 格式；重复网址自动合并。本地图片和网络图片可以一起导入，每次合计最多 100 张。
- 网络图片会在保存时下载到本机，生成缩略图，之后可以离线浏览并正常导出备份。请使用直接返回图片的完整网址；网页地址、失效链接、需要登录或受防盗链限制的地址可能无法导入，软件会显示失败原因。一批图片中有下载或解码失败时，不会创建不完整的新图集或追加部分图片。
- 首页通过图片卡片浏览，支持搜索、分类、收藏和排序。
- 分类可以自定义：导入或编辑图集时，直接在“分类”栏输入新名称，保存后会自动加入分类列表。点击侧边栏“图集分类”旁的“管理”，可新增、重命名或删除分类；重命名会同步到已有图集，删除分类后相关图集归入“未分类”，图片和网盘链接保留。分类列表保存在本地数据库，重启后仍然有效。
- 点击卡片查看详情和图片，使用全屏浏览查看大图。
- 在图片集编辑界面添加一个或多个网盘链接，填写提取码、解压密码和备注。链接显示在详情页底部。
- 为百度网盘链接开启时间同步，可在同步界面查看检测记录，也可立即检测。
- 网盘链接会单独显示有效性状态；可检查单条链接，也可在“网盘同步”页面检查全部链接。关闭某条链接的时间同步仍可检查它是否失效。
- 在“图库设置 → 备份与恢复”中点击“导出备份”，可选择按分类整理的 Excel 清单，或同时保存全部原图和数据库的完整 ZIP 备份。
- 在“图库设置 → 备份与恢复”中点击“导入备份”，选择 ZIP 或 Excel 文件，预览内容后勾选要导入的图集；默认跳过已存在的图集，也可选择作为新副本导入。

支持 JPG、PNG、WebP、GIF 和 AVIF。单张图片最多 30 MB，每次最多导入 100 张，每个图片集最多 1000 张。

### 可选示例图库

项目附带自然风光和城市照片，保存在 `public/demo/`，导入后可离线浏览；图片来源见该目录下的 `credits.txt`。先启动软件并创建账号，然后在另一个终端设置自己的登录凭据并执行：

```powershell
$env:GALLERY_USERNAME = Read-Host '图库用户名'
$galleryCredential = Get-Credential -UserName $env:GALLERY_USERNAME -Message '输入图库登录密码'
$env:GALLERY_PASSWORD = $galleryCredential.GetNetworkCredential().Password
node scripts/seed-demo.mjs
Remove-Item Env:GALLERY_USERNAME, Env:GALLERY_PASSWORD
Remove-Variable galleryCredential
```

此命令使用现有账号登录，只在图库为空时导入示例，已有内容时会跳过，不会覆盖自己的图片；执行结束后会退出此次脚本会话。示例图集可以在界面中删除。若服务使用其他端口，先将 `GALLERY_URL` 环境变量设为自己的图库服务地址。脚本不会自动创建账号，登录凭据仅发送到指定地址，不跟随重定向。

## 更新时间与每日检测

图片集标题下显示的是内容更新时间。尚未取得网盘时间时，使用本地图片集的更新时间；成功读取百度网盘文件信息后，可同步为远端文件的修改时间。

远端时间取自分享中全部可读取文件（包含子目录）的最新 `server_mtime`，不是分享页面的检测时间。删除文件，或加入保留旧修改时间的文件，不一定使显示时间变新；删除具有最新修改时间的文件时，显示时间也可能回退。因此这个字段表示当前文件的最新修改时间，不能代表每一次目录增删操作。

启用自动同步时，服务每隔 **24 小时**检测链接；间隔从该链接上一次检测计算。服务关闭期间不会检测，重新启动后会处理已经到期的检测。若需要全天自动检测，应保持软件运行，或使用下方 Docker 方式持续运行。

**「上次检测时间」和「网盘更新时间」是两个不同字段。** 检测成功但内容未变化时，不会把当天检测时间写成图片更新时间。读取失败时保留已有时间，并显示错误。

百度网盘的公开分享页面可能要求提取码、登录或验证码，也可能限制请求。软件只能同步实际可读取的远端文件信息，无法保证任意分享链接都可自动读取。分享过期、提取码错误、验证拦截时需要处理后再试；软件不会绕过验证码或编造更新时间。添加真实链接后，应先点一次立即检测，确认该链接可以读取。

已于 **2026-10-07** 使用实际百度网盘分享完成递归目录读取和更新时间同步验证。不同分享和未来页面变化仍可能影响读取结果。

设置中可选填百度网盘 Cookie，供本地服务访问需要登录的分享使用。Cookie 仅存于本地数据，不会作为设置接口响应返回浏览器；通过“导出备份”生成的文件不包含 Cookie。手动复制整个数据目录仍会包含 Cookie，应妥善保管。无法读取的网盘链接仍可以在图片集底部正常跳转。

### 网盘链接有效性

百度网盘链接支持单独检查有效性：在图集详情底部检查单条链接，或在“网盘同步”页面检查全部链接。结果和上次检查时间会保存，链接的有效性检查不会改变图集内容更新时间，也不会自动删除链接或图片。

- **有效**：已确认分享可以访问。
- **已失效**：百度网盘明确返回分享取消、过期或不存在等失效结果。
- **需要提取码、提取码错误、需要登录、需要验证**：需先补充对应信息或完成验证，不能据此判断分享失效。
- **网络异常、暂无法判断**：本次请求失败或没有取得足以判断的结果；不会将这类情况标成已失效。
- **暂不支持**：其他网盘暂不自动判断有效性，仍可正常点击跳转。

开启图库设置中的每日自动检测与同步后，软件会按每条百度链接上次有效性检查时间，间隔 **24 小时**检查一次。有效性检查与链接的“同步更新时间”开关分开：即使不需要同步图集时间，也会检查百度链接；关闭全局自动检测则暂停这两项定时任务，仍可手动检查。服务关闭期间不会运行任务，重新启动后会处理已到期的检查。

## 数据保存与备份

- `data/gallery.db`：图片集、链接、设置、检测记录及图库账号、头像、登录会话、防暴力破解状态和邮件安全记录。图库密码保存为加盐哈希，SMTP 授权码加密保存。
- `data/security-mail.key`：首次保存 SMTP 授权码时生成的本地解密密钥；使用自定义 `DATA_DIR` 时保存在对应数据目录。
- `data/uploads/`：导入的图片与缩略图。

数据会保留到下次启动。更新代码或重新构建页面不会要求删除数据。

### 在软件中导出

点击“导出备份”，选择格式后生成并下载文件。导出范围是全部分类和图集，不受当前搜索或分类筛选影响；导出不会改变图片更新时间和网盘检查计划。

| 格式 | 包含内容 | 适用场景 |
| --- | --- | --- |
| Excel 清单（`.xlsx`） | 每个分类一个工作表，含序号、标题、时间、图片、网盘链接、提取码、解压码；图片列内嵌图集封面 | 在 Excel 中浏览、查找、整理和留存网盘资料 |
| 完整备份（`.zip`） | 同样的 Excel 清单、全部原图和缩略图、数据库快照、完整资料清单及恢复说明 | 迁移电脑或恢复整个图库 |

Excel 保留空分类；分类名称超出 Excel 的 31 字符限制、含特殊字符或名称冲突时，工作表会使用合法且不重复的名称，完整名称对应关系见说明页。同一图集有多个网盘链接时分行列出，各自对应的提取码和解压码以文本保存，开头的 `0` 不会丢失。

表格中的“时间”是图集当前显示的内容更新时间，使用香港时间（UTC+8）和可排序的 Excel 日期格式；成功同步网盘的图集采用已同步的远端时间。导出时不会额外触发网盘检测。

**Excel 仅包含图集封面和表格资料，不包含每张原图，也不能单独还原整个图库。** 若要完整备份，请选择 ZIP。ZIP 会保存分类、简介、标签、收藏、链接、同步状态、有效性检查结果、计划和检测记录；百度登录 Cookie、图库账号、头像、登录会话、防暴力破解状态、SMTP 与 WebDAV 设置和密钥、安全记录及已知登录来源不会导出。若发现原图或缩略图缺失，完整备份会报错，避免将不完整的文件当作成功备份。

### 每周自动备份

管理员在“图库设置 → 备份与恢复 → 自动备份”中管理计划。默认开启，每周日 **03:00（香港时间 UTC+8）**执行，可修改星期和时间，也可暂停或点击“立即备份”。服务需要保持运行；停机期间错过的计划会在重新启动后补做一次，不会一次性堆积多份任务。

完整 ZIP 保存在 `data/auto-backups`（自定义 `DATA_DIR` 时使用对应目录），与手动导出缓存分开。成功生成并校验新备份后，默认保留最近 **7 份**，多余的按最旧顺序清理；正在下载的文件会受保护，每小时重试清理，临时超额最多 8 份。管理员可在设置中下载这些备份，再通过“导入备份”恢复（超过导入容量限制时使用下文的手动恢复）。

每次备份前检查原图是否完整、预计工作空间和磁盘可用空间，并保留 **512 MiB**安全余量。空间不足时按以下顺序处理：

1. 在管理员页面持续显示警告，并通过已启用的邮件提醒配置通知管理员。等待 **24 小时**，期间重新检查空间；若空间已足够，即可继续备份。
2. 等待期结束且仍不足，逐个删除最旧的完整自动备份。每删除一份，重新读取实际可用空间，足够后立即停止清理并生成新备份。
3. **已有完整备份仅剩 1 份时，不再删除**；若仍不够，本次备份停止并提醒管理员。管理员释放空间后可点击“立即备份”，或等待后续计划。没有历史备份时也不会删除其他文件腾空间。

提醒时间和等待期限保存到数据库，服务重启不会重新计时。实际修改或暂停计划会结束旧的等待事件，新计划重新检查空间。仅反复保存相同设置不会延长等待期限。生成中断、写入失败或校验失败不会被计为成功备份；中间文件会清理，原有完整备份会继续保留。超出单次备份容量限制或无法验证源文件时，不会为了尝试备份而先清理旧文件。

邮件沿用“安全与邮件提醒”中保存的收件人，需要启用邮件提醒并配置 SMTP；未配置时仍保留页面警告和事件记录。备份警告、停止和恢复事件会合并提醒，不会每分钟重复发信。自动备份与手动生成共用一个生成任务名额，避免多个 ZIP 同时占用空间。单次自动生成最多运行 30 分钟，超时取消后释放中间资源，并提醒管理员；可重试的失败每小时重试一次。

自动 ZIP 的内容范围与手动完整 ZIP 相同，包含图库原图和资料，**不包含登录账户、头像、Cookie、SMTP/WebDAV 密钥等账户或安全数据**。自动备份计划也不随图库 ZIP 导入覆盖当前计划。自动清理仅操作本程序确认的自动备份，不会删除图库原图、手动下载的备份或目录中的未知文件。没有启用 WebDAV 时，备份与图库位于同一磁盘；需要应对磁盘损坏时，请另行下载保存到其他存储设备。

#### WebDAV 远程副本

管理员可在同一页面启用 WebDAV。填写服务商提供的 HTTPS 文件夹地址、用户名和密码，先在远端创建好目录，再点“测试连接”；测试会检查证书、账号和目录读取权限。每次本地完整 ZIP 通过校验后，服务会将其上传到该目录，并在远端只保留最近 7 个由拾光生成的备份文件。远端清理只识别 `lumina-gallery-auto-...zip` 文件，不会删除目录中的其他内容。

远端连接失败时，本地完整备份仍保留，管理员会收到失败提醒；服务每小时重试上传同一份 ZIP，不会为重试反复生成新的本地备份。密码以 AES-GCM 加密保存在服务器数据库，密钥位于数据目录的 `security-mail.key`，不会返回浏览器或写入图库 ZIP。手动复制整个数据目录时，数据库和此密钥都必须一起保护。

出于服务器请求安全限制，仅接受公网可访问的 HTTPS 地址和标准 443 端口；无法连接私有 IP、HTTP 或自定义端口的 WebDAV 服务。WebDAV 服务需要允许 PROPFIND 列目录、PUT 上传和 DELETE 清理；“测试连接”只验证 HTTPS、凭据和目录读取，实际上传与清理权限会在备份时验证。

### 在软件中导入备份

在“图库设置 → 备份与恢复”中点击“导入备份” → 选择 `.zip` 或 `.xlsx` 文件 → 预览图集、分类和图片数量 → 勾选图集 → 点击“导入所选”。仅预览或取消不会修改图库。预览保留一小时，过期后重新选择文件即可。

- **完整 ZIP 备份**：选择拾光导出的 ZIP，可恢复全部原图、标题、分类、简介、标签、收藏、网盘链接、提取码和解压密码、更新时间、链接同步状态和有效性检查结果。较早版本不包含有效性结果的备份仍可导入，相关链接会等待重新检查。所选图集及备份中的空分类会加入当前图库；备份中的软件设置和历史同步日志不会合并，当前设置、百度登录 Cookie 和图库登录账号保留。
- **Excel 清单**：支持软件导出的工作簿，也支持按“序号、标题、时间、图片、网盘链接、提取码、解压码”排列的表格。每个工作表作为一个分类，软件导出时的完整分类名从说明页恢复。同一工作表中相同序号的多行合为一个图集；图片列中的内嵌图片会保存到本机，外部图片网址不会自动下载。Excel 日期按香港时间（UTC+8）读取，文本密码中的前导零保留。
- Excel 没有的原图、简介、标签、收藏和检查记录无法还原。为保留导入的表格时间，Excel 导入的链接默认不开启自动同步，可在编辑图集时自行开启。公式单元格需要先转成文本或普通值再导入。
- 重复识别依据 ZIP 中的图集编号或 Excel 行内容，不按标题判断；同标题的不同图集可以同时存在。默认跳过已存在的图集，也可选择“作为新副本导入”；两种方式都不会覆盖现有图集。修改过内容的 Excel 图集可能识别为新图集。

ZIP 文件上限 2 GB，Excel 文件上限 128 MB。损坏的压缩包、缺失原图或无法解码的图片会显示错误；导入失败时不会保留部分图集。ZIP 中的数据库文件不会在此流程中打开或替换当前数据库。

### 从完整 ZIP 替换整个图库（手动恢复）

如需连同备份中的设置和历史同步日志一起恢复，可采用以下方式；这会将当前图库替换为备份时的状态。

1. 停止软件：在服务终端按 `Ctrl+C`；使用 Docker 时执行 `docker compose down`。
2. 解压备份 ZIP，并先将当前 `data` 目录另存一份，防止误覆盖已有图库。
3. 使用备份中的整个 `data` 目录替换软件的数据目录，确保 `gallery.db` 和 `uploads` 来自同一份备份。使用自定义 `DATA_DIR` 时，替换对应位置。
4. 重新启动软件，在本机重新创建图库账号，然后核对分类、图片和网盘链接；需要登录网盘时重新填写 Cookie。软件导出的 ZIP 不包含图库账号和登录会话。

ZIP 内也附有 `恢复说明.txt`。恢复会使用备份时的图集和检查计划；重启后已到期的链接会按自动同步设置继续检查。不要在服务运行时覆盖数据库，也不要把旧目录中的 `gallery.db-wal`、`gallery.db-shm` 混入备份目录。

仍可采用手动备份方式：先停止服务，再复制整个 `data` 目录；恢复时同样先停止服务并保留现有目录的副本，再还原整份目录。手动复制的数据目录包含账号密码哈希、头像、会话、百度 Cookie、SMTP 配置及其解密密钥、WebDAV 配置及其密码解密密钥、安全记录，与软件导出文件的范围不同。要保留邮件或 WebDAV 配置，请让 `gallery.db` 和 `security-mail.key` 来自同一份数据目录备份。

默认仅监听本机。当前版本支持多个账户共用图库，并由管理员与普通只读账户的权限控制操作范围。

可通过进程环境变量调整：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3210` | 服务端口 |
| `HOST` | `127.0.0.1` | 服务监听地址 |
| `DATA_DIR` | `./data` | 数据保存目录 |
| `ALLOWED_HOSTS` | 空 | 额外允许访问的主机名或 IP，多个值以英文逗号分隔；Docker 部署时可在 `.env` 设置并传入容器 |
| `TRUSTED_PROXIES` | 空 | 明确可信的反向代理 IP 或 CIDR，英文逗号分隔；空值时不信任转发头。Docker 部署时可在 `.env` 设置并传入容器 |

PowerShell 示例：

```powershell
$env:PORT = '3211'
./start.ps1
```

## 长期运行与空间保护

服务已加入以下限制，默认启用，无需在页面里设置：

| 对象 | 限制与清理方式 |
| --- | --- |
| 运行错误日志 | 写入 `data/.logs/runtime.log`，每份 2 MiB，连同轮转文件最多 3 份（约 6 MiB）；同类错误每分钟最多记录一次，并汇总被抑制次数；全局每分钟最多 60 条。只记录事件名、错误类型和错误码，不记录密码、Cookie、请求正文或错误堆栈。日志写入失败会退避，不递归记录自己的错误。 |
| Docker 控制台日志 | Compose 配置每份 5 MB、最多 3 份，避免容器不断重启时持续堆积标准输出。其他服务管理器或自定义重定向日志需自行设置轮转。 |
| 同步与安全记录 | 同步记录保留最近 90 天、最多 1000 条；安全记录也有时间、数量限制，并在空闲时清理。过期会话、限流状态、已删除账户的来源记录会定期清除。 |
| 导出备份缓存 | 服务端最多保留 3 个导出、总计最多 8 GiB，最长保留 1 小时；新备份可能提前淘汰旧的未下载缓存。已下载到自己电脑的备份不受影响。下载最多同时 4 个，空闲 2 分钟或持续 30 分钟后断开。 |
| 自动备份 | 每周执行，本机完整备份保留最近 7 份；可选 WebDAV 远程副本也保留最近 7 个程序生成的 ZIP。空间不足先提醒并等待 24 小时，随后逐份清理最旧本机备份，但始终留下至少 1 份。WebDAV 失败时保留本机备份并每小时重试同一份；部分文件和未完成包不计为成功备份，下载、生成及清理任务均有并发限制。 |
| 导入备份暂存 | 最多 3 个待确认预览、总计 8 GiB，预览 1 小时过期。导入完成会释放图片对象和临时副本，重复提交所需的小型结果最多保留 64 个。服务重启时清除可验证属于本程序的失联导入、导出缓存。 |
| 图片上传与解码 | 最多 2 个图片导入同时处理；每批本地与网络图片合计不超过 300 MiB。超时、断连和失败会清理中间文件；解码有时间限制，完成后释放解码器。图片处理缓存限制为 32 MiB，禁用文件缓存。 |
| 网盘任务 | 相同任务合并，最多排队 32 个不同任务；HTTP 同步等待者最多 8 个，断连后名额仍保留到任务结束。服务停止时取消正在执行的网络请求，并跳过尚未执行的任务。 |
| 文件维护 | 启动后及每 10 分钟检查一次；只删除超过 24 小时、名称可确认由程序生成的上传暂存，以及图库中已无引用的图片残留。保留有效原图、未知文件和符号链接。 |
| 数据库维护 | 定期检查点回收 WAL，并释放 SQLite 缓存；新数据库使用增量空间回收。256 MiB 以内的旧数据库在无活动请求且磁盘充足时转换，较大的旧数据库继续复用已释放页，不自动执行大规模重建。 |
| 磁盘余量 | 写入前按预计大小检查，至少预留 512 MiB；空间不足会拒绝新的大文件任务，返回可操作的提示。 |

HTTP 连接、上传、图片解码、网络读取与邮件发送均有超时；清理任务不会重叠排队。网页后台轮询有请求截止时间，会取消被新请求替代的读取，切换页面或退出登录时释放相关请求、监听器和定时器。

同一数据目录应只运行一个实例；直接启动正式服务时会检查运行锁。不要让多个容器或不同主机同时共享同一数据目录。不要在服务运行时手动删除 `.runtime-lock`、SQLite 的 `-wal` 或 `-shm` 文件。

这里限制的是程序额外产生的日志、队列和缓存。导入的有效原图、图集资料以及你下载保存的备份会随收藏增加而增长，程序不会为了腾空间自动删除它们。导出 8 GiB 指已完成、保留下载文件的总量；生成过程中还会短暂使用 Excel、数据库快照等工作文件，完成或失败后清除。缓存上限也不是进程总内存上限：图片解码、Excel 解析和压缩时仍有临时工作内存；操作结束后内存可被进程复用，操作系统显示的占用不一定立即回到启动数值。磁盘余量检查无法阻止其他软件同时写满磁盘，仍应留足实际图库容量。

实现依据：[SQLite 空间回收和 WAL 设置](https://www.sqlite.org/pragma.html)、[Node.js HTTP 超时](https://nodejs.org/api/http.html#serverrequesttimeout)、[Sharp 缓存限制](https://sharp.pixelplumbing.com/api-utility/#cache)。

## Docker

已安装 Docker 的电脑可运行：

```sh
docker compose up -d --build
```

Compose 将宿主机 `./data` 挂载为持久数据目录，服务只对宿主机本地端口开放。容器运行时执行每日检测；通过下文的 HTTPS 反向代理访问页面。

VPS 通过 Nginx 或其他反向代理提供域名访问时，保持端口只绑定 `127.0.0.1`，并在项目 `.env` 中设置 `ALLOWED_HOSTS=gallery.example.com`（填写自己的域名，不带协议、端口或路径）。反向代理需把原始 `Host` 头传给容器并提供 HTTPS；不要把 `3210` 端口直接开放到公网。

`TRUSTED_PROXIES` 只填连接到图库的反向代理在容器网络中的实际源 IP 或精确 CIDR。先从 Docker 网络配置确认代理地址；不要填写所有来源、任意客户端地址或宽泛网段。代理必须覆盖 `X-Forwarded-Proto`、`X-Forwarded-For`、`X-Forwarded-Host`，不能直接采用客户端传来的值。配置后服务才识别代理终止的 HTTPS，并按实际来源做登录限流和新来源提醒；空值不会信任任何转发头，公网请求会被拒绝。

单层 Nginx 反向代理示例（替换域名、证书路径，并配置实际代理来源）：

```nginx
server {
    listen 80;
    server_name gallery.example.com;
    # 明文口令请求直接拒绝；页面导航跳转到 HTTPS。
    if ($request_method !~ ^(GET|HEAD)$) { return 403; }
    return 308 https://gallery.example.com$request_uri;
}
server {
    listen 443 ssl;
    server_name gallery.example.com;
    ssl_certificate /etc/letsencrypt/live/gallery.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/gallery.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    location / {
        proxy_pass http://127.0.0.1:3210;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
```

拒绝 HTTP 请求无法追回已在明文链路上传出的内容；请从 HTTPS 登录页开始访问，使用有效证书，并确保浏览器到代理及任何跨主机代理链路都加密。上述示例假设 Nginx 与后端在同一 VPS；多层代理需要逐层限定可信来源和正确覆盖转发头。

**Docker 首次使用时，在容器终端初始化账号**：容器端口转发不属于直接本机连接，因此网页不会开放首次账号创建。服务启动后，在宿主机的交互式终端执行：

```sh
docker compose exec lumina node scripts/setup-admin.mjs
```

按提示输入用户名、密码和确认密码，再回到浏览器登录。密码输入不会显示，也不会作为命令行参数或写入日志；请勿通过管道或重定向提供密码。脚本只连接容器内部的 `127.0.0.1`，并使用容器的 `PORT`；已有账号时会直接退出，不会覆盖账号或重置密码。如果复用的数据目录已经在本机创建过账号，直接使用原账号登录即可，无需初始化。

在服务器直接运行 Node.js 时，也可在同一服务器的终端执行 `node scripts/setup-admin.mjs`，需先启动服务；使用自定义端口时给脚本设置相同的 `PORT`。本机 Windows 浏览器仍可按前文通过本机页面完成首次设置。

```sh
docker compose logs -f
docker compose down
```

在 Linux 上使用现有 `data` 目录时，需保证容器用户 UID `1000` 对目录可写。停止容器不会删除宿主机的 `data` 目录。
